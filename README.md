# AI 라운지 · AI Lounge

공개된 AI 자료를 읽고 그림과 글로 정리하는 개인 프로젝트입니다. 강연 인사이트, 날짜별 데일리, 월간 소개 자료를 함께 보관합니다.

| AI 소식 읽기 | https://hs321-lee.github.io/ai-lounge/#daily | 최신 AI 브리핑 본문과 원문을 바로 표시 |
| 인사이트 모음 | https://hs321-lee.github.io/ai-lounge/#library | 원자료와 핵심 세 가지 요약을 각각 열기 |
| 함께 보기 · 월별 자료 모음 | https://hs321-lee.github.io/ai-lounge/#monthly | 실제 발행한 월의 목록에서 자료 선택 |

기본 주소와 `#home`은 라운지 홈을 엽니다. 홈 / AI 소식 / 인사이트 / 함께 보기 메뉴는 모든 화면에서 같은 이름과 순서로 표시하며, AI 라운지 로고는 홈으로 이동합니다. 데일리는 `#daily`와 기존 `#post/아이디` 주소에서 읽습니다. 월별 목록은 `#monthly`에서 열고, 선택한 월은 `#monthly/YYYY-MM`에서 읽습니다. 기존 발표 장면과 `#post/monthly-2026-10` 공유 주소는 유지합니다. 없는 월은 목록으로 돌아가는 안내를 표시하며, 그 밖의 알 수 없는 주소는 홈으로 안내합니다.

모든 화면과 저장소는 공개 상태입니다. 용도별 화면 분리는 접근 제한이나 비공개 처리가 아니므로 비공개 자료는 저장하지 않습니다.

## 이번 달 구성

데스크톱 발표용 월간 소개입니다. 표지 → 1편 → 2편 → 3편 → 4편 후속 소개 한 장 → 다음 소개(Herdr) 순서로, 한 화면에 한 장면씩 보여 줍니다.

1. 치과 AX 전환기 1–3편: 각 편의 원문 링크와 원문에 실린 캡처를 그대로 사용 (자르거나 새로 가리지 않음, 검은 가림은 원문 작성자가 한 것)
2. 4편 후속 소개: 완료 기준과 교차검토를 한 장으로 소개하고, 상세 인사이트와 이전한 블로그 원문으로 연결
3. 다음 소개 · Herdr: 한 줄 소개, 핵심 기능, 에이전트 스킬 설치 명령. 이미지는 Herdr 공식 저장소(Apache-2.0)의 스크린샷

수치는 작성자 보고이며 독립 검증한 값이 아닙니다. PDF 원본은 올리지 않습니다.

발표 조작:

- `→` / `←`: 다음·이전 장면으로 이동
- 표지 카드의 `바로 가기`: 해당 편으로 이동, `원문 ↗`: 원문 새 창
- 화면 클릭: 원본 해상도로 크게 보기, `Esc` 또는 `닫기`로 나가며 초점이 원래 화면으로 돌아옴

모든 장면은 스크립트 없이도 보입니다. 모션은 장면이 들어올 때 한 번 26px 상승·페이드하고, 모션 감소 설정에서는 꺼집니다. 1100px 이하에서는 한 줄 배치로 바뀝니다.

## 자료를 쌓고 반영하기

공개 출처로 확인한 자료와 구분해 표시한 활용 해석을 월간 소개에 반영합니다. 기존 아침 브리핑의 AI 부분은 준비 자료로 계속 누적하고, 월간 발표에 쓸 내용만 골라 올립니다.

- 원본 데이터: `data/posts.json`
- 데일리 화면: `type: daily` 최신 기록의 날짜·오늘 핵심 → 번호 목차 → AI 인사이트 → GitHub·스킬 발견 → 오늘의 실험을 표시. 모바일은 1열이며 기본 요약은 바로 읽고 상세·설치·주의점·집계 근거는 펼칩니다.
- 월간 발표: `type: monthly` 항목만 별도로 표시
- `type: guide`는 `published: true`인 자료만 인사이트 모음에 표시
- 같은 날짜의 데일리 기록은 중복 생성하지 않고 보완
- 데일리 내부 `monthlyCandidates`에 선별 이유와 출처만 누적하며, 월간 글은 별도 편집 후 발행

기존 브리핑 일정과 데이터 계약을 그대로 쓰며 별도 AI 수집기나 추가 일정을 만들지 않습니다. 외부 소식을 반영할 때 원문과 날짜를 확인하고, 개인 경험과 활용 제안을 구분합니다.

### 데일리 편집 기준

기존 아침 브리핑과 같은 실행에서 공개 AI 소식을 선별합니다. 모델·도구·저장소별 고정 할당량은 두지 않습니다. **주요 모델 소식, 코딩 도구의 큰 업데이트, 급상승 스킬·GitHub 저장소, 공식 예정 사항** 중 사용자에게 중요한 변화부터 고릅니다. 기존 화면의 `sections`, `radar`, `recipe` 계약은 유지하며, 근거가 부족한 날은 수를 채우지 않고 확인 범위를 설명합니다.

- **선정 우선순위:** 주요 모델의 출시·능력·가격·사용 한도 변화, 코딩 도구·에이전트·스킬의 중요한 기능 변화, 증가 근거가 있는 GitHub 저장소, 공식 발표한 예정 사항을 비교합니다. 영향과 새로움이 큰 소식을 먼저 선정합니다. 운영 팁·일반 점검 방법은 실제 중요한 변화와 연결될 때만 다루며, 주요 소식을 대신하는 독립 항목으로 채우지 않습니다.
- **원문과 시점:** 공식 발표·릴리스·문서를 우선합니다. 최근 24시간을 먼저 확인하고 부족하면 최근 7일로 넓힙니다. 발표일과 실제 제공일을 구분하고, 정식·프리뷰 여부와 적용 요금제·플랫폼·제약을 확인합니다. 확인한 사실, 변화의 의미, 활용 제안을 나눠 씁니다.
- **예정 사항:** 공식 출처에 날짜와 제공 범위가 있으면 ‘공식 확정’, 공식 예고만 있고 일정이 정해지지 않았으면 ‘공식 예고·일정 미정’으로 표시합니다. 공식 근거가 없는 일정은 ‘미확인’으로 구분하고 확정 소식에 포함하지 않습니다. 예정일이 지났다는 이유만으로 출시됐다고 쓰지 않으며, 실제 제공 여부를 후속 확인합니다.
- **GitHub·스킬:** 실제 README·릴리스·커밋·라이선스를 확인합니다. 용도, 선정 이유, 시작 방법, 제약과 관찰 날짜를 적습니다. ‘급상승’에는 관찰 기간과 해당 기간의 Stars 증가량 또는 기간이 명시된 공식 Trending 근거를 붙입니다. 누적 Stars만으로 급상승을 판단하지 않습니다. 증가 근거가 없으면 ‘추천 저장소’로 표시하고, 중요한 새 변화가 있을 때만 선정합니다.
- **활용 프롬프트:** 선정한 소식 중 활용하기 가장 적합한 항목 하나에 짧고 복사 가능한 `recipe.prompt`를 연결합니다. 필요한 입력, 요청할 작업, 결과 확인 기준을 적고 기존 복사 버튼을 유지합니다. 단계와 제약은 `recipe.steps`, `recipe.limitation`에 남깁니다. 직접 실행하지 않았다면 활용 제안이라고 표시하며, 활용 프롬프트는 뉴스 건수에 포함하지 않습니다.
- **중복과 과거 기록:** 같은 발표나 저장소를 매일 다시 추천하지 않습니다. 중요한 업데이트·새 활용·후속 검증이 있을 때만 달라진 점과 재소개 이유를 적습니다. 새 선정 기준은 이후 소식에 적용합니다. 사용자가 승인한 이번 과거 8개 날짜의 소급 점검은 각 게시일에 이미 공개된 자료만 사용해 사실·선정·표현을 교정하고 필요하면 정정 이유를 남깁니다. 이후에는 과거 원고를 임의로 다시 쓰지 않습니다.
- **모바일 편집:** `title`, `sections[].heading`, `radar[].headline`에는 실제 모델·도구·저장소 이름과 새 변화를 짧게 씁니다. 인사이트 `summary`는 사실 1–2문장, `relevance`는 의미·활용 대상 한 문장입니다. 요약은 CSS로 잘라 숨기지 않고 편집으로 짧게 유지합니다. 전체 `body`, 해석 `takeaway`, 실행 `action`은 상세에 보존합니다. 기존 기록에 새 필드가 없으면 본문을 그대로 보여 줍니다. 목차는 실제 항목에서 자동 생성되며, 레시피 프롬프트는 복사 버튼과 수동 선택을 지원합니다.
- **월간 후보:** 데일리 중 소개할 만한 내용만 `monthlyCandidates`에 남깁니다. 후보 추가는 월간 발행이 아니며 월간 화면에 자동 노출하지 않습니다.


Node.js 20 이상에서 JavaScript 문법과 콘텐츠의 필수 필드·중복 ID·날짜·HTTPS 출처를 검사합니다.

## 콘텐츠 계약

`templates/monthly.json` 또는 `templates/daily.json`을 복사해 `data/posts.json`의 `posts` 배열에 추가합니다. 템플릿은 화면에 직접 표시되지 않습니다.

| 필드 | 내용 |
| --- | --- |
| `id` | 영문 소문자·숫자·하이픈으로 만든 고유 ID |
| `type` | `monthly`, `daily`, `guide` |
| `date` | `YYYY-MM-DD` |
| `title`, `summary`, `author` | 제목, 요약, 작성자 |
| `tags` | 주제 문자열 배열 |
| `sections` | `{ "heading": "소제목", "body": "본문" }` 배열. 일반 텍스트·줄바꿈 지원. 월간 기록은 한 항목이 발표 장면 하나 |
| `sections[].kind` | 선택 항목: `"chapter"`이면 편 구분 화면. `part`(예: `1편`), `date`, `url`(원문) 필요 |
| `sections[].insightId` | 선택 항목: 월간 chapter에서 연결할 발행된 인사이트 ID. 내부 요약 링크로 표시 |
| `sections[].media` | 선택 항목: 이미지 배열. 각 항목은 `src`, `width`, `height`, `alt`, `caption`. `assets/dental/`, `assets/herdr/`의 파일만 사용 |
| `sections[].stats` | 선택 항목: `{ "value": "77%", "label": "설명" }` 배열 |
| `sections[].points`, `steps`, `code` | 선택 항목: 문자열 배열. 요점 목록, 단계 흐름, 명령어 블록 |
| `sources` | `{ "title": "원문 이름", "url": "https://…" }` 배열 |
| `highlights` | 선택: 첫 화면 핵심 문자열 최대 3개 |
| 데일리 `sections[].label`, `date`, `takeaway`, `action`, `url` | 선택: 분류·발표 날짜·해석·활용 행동·공식 원문. 기존 `heading`, `body`와 함께 사용 |
| 데일리 `sections[].summary`, `relevance` | 선택: 기본 표시할 짧은 사실 요약·왜 중요한지 한 문장. `summary`가 있으면 전체 `body`·해석·실행은 native details로 펼쳐 읽기 |
| `radar` | 선택: `{label, repo, url, description, signal, checkedAt, sourceUrl, why, try, limitation}` 배열. 검증된 GitHub 저장소, 선정 근거와 관찰 날짜. 선택 `headline`은 용도가 드러나는 짧은 제목 |
| `recipe` | 선택: `{heading, description, steps:[], prompt, limitation}`. 실행해 볼 절차와 요청 예시 |
| `monthlyCandidates` | 선택: `{title, reason, url}` 배열. 준비 데이터만 저장하며 월간 발표 자동 발행 금지 |

월간 목록은 `type: monthly`의 실제 발행 월만 최신순으로 모읍니다. 새 월간 항목을 추가하면 목록에 함께 표시하며, 없는 달을 만들지 않습니다. 각 `sections` 항목이 발표 장면 한 개입니다. 같은 월에 자료가 여러 개면 모두 표시하고 고유 `#post/아이디`로 연결합니다. `#monthly/YYYY-MM`은 그 달의 최신 자료를 엽니다. 초안은 제목·요약에 준비 상태를 명확히 적습니다. 데일리 기록은 최소 한 개의 HTTPS 원문이 필요합니다.

## 배포

현재 운영 주소는 위의 GitHub Pages이며 **main / (root)**를 소스로 사용합니다. Cloudflare 이전 준비만 추가한 상태입니다. 새 주소에서 검증하기 전에는 기존 Pages와 저장소 공개 설정을 바꾸지 않습니다. 콘텐츠 검사는 `Validate content`에서 계속 실행됩니다.

### Cloudflare 이전 준비

목표는 **GitHub 저장소 private + 로그인 없는 공개 웹사이트**입니다. 저장소가 private여도 배포한 HTML·JSON·이미지·스킬 파일은 누구나 내려받을 수 있습니다. 개인 정보와 비밀키는 아래 공개 경로에 넣지 않습니다.

1. Cloudflare Pages에서 이 저장소만 GitHub 연결 대상으로 허용합니다. Production branch는 `main`으로 설정합니다.
2. 실제 사용할 정식 HTTPS 주소를 확정하고 환경 변수 `SITE_URL`에 입력합니다. 호스트 주소만 사용하며 경로·쿼리·프래그먼트는 넣지 않습니다. 미리보기 주소를 정식 주소로 자동 사용하지 않습니다.
3. Framework preset은 `None`, Build command는 `npm run check && npm run build`, Build output directory는 `dist`, Node.js는 `22`로 설정합니다. `SITE_URL`이 없거나 잘못되면 빌드가 실패합니다. 첫 배포 전 주소 확인이 필요하면 프로젝트의 자동 배포를 중지한 상태에서 먼저 주소와 환경 변수를 설정합니다.
4. Pages의 Metrics에서 Web Analytics를 활성화하고 다시 배포합니다. 실제 방문과 `#home`·글별 화면 전환의 통계 집계 여부를 검증합니다.
5. 새 주소에서 홈·AI 소식·인사이트·월별 자료·공유 링크·이미지·스킬 다운로드와 다음 콘텐츠 갱신을 확인합니다. 그 뒤 기존 Pages를 종료하고 저장소를 private로 전환합니다. GitHub Free에서 먼저 private로 바꾸면 기존 Pages가 중단됩니다.

`npm run build`는 `dist/`를 새로 만들며 다음 경로만 배포합니다.

- `index.html`, `tokens.css`, `assets/**`, `skills/spec-six/SKILL.md`는 공개 파일입니다. `assets/`의 모든 파일도 공개 대상으로 취급하므로 개인 자료를 넣지 않습니다. 심볼릭 링크는 허용하지 않습니다.
- `data/posts.json`은 공개용으로 복사합니다. `published: false`인 글과 `published: true`가 아닌 guide, 화면에서 쓰지 않는 `monthlyCandidates`는 출력에서 제외합니다. 나머지 JSON 필드와 공개 assets는 모두 방문자가 볼 수 있습니다.
- README·scripts·templates·`.github`와 그 밖의 경로는 복사하지 않습니다. `dist/`는 git에 저장하지 않습니다.

정식 주소를 지정하면 출력 파일의 canonical·Open Graph 주소와 기존 자기주소의 스킬 다운로드 링크를 새 주소로 바꿉니다. 원본 HTML·JSON과 기존 브리핑 일정·콘텐츠 계약은 변경하지 않습니다. 위 바로가기와 공개 상태 설명은 실제 이전 완료 후 새 운영 상태에 맞춰 갱신합니다.

이전 상태로 되돌리려면 변경을 revert해 `main`에 반영합니다. 회사 내부 정보·개인정보·비밀키·비공개 자료는 공개 저장소에 올리지 않습니다.

## 데일리 상단 요약 이미지

**2026-10-30 사용자 지시로 그림 작업을 재개했습니다.** 기존 데일리 8개 날짜의 내용과 그림을 각 게시일 기준으로 함께 점검하고, 검증·선정한 본문과 일치하는 요약 이미지로 교체합니다. 이후 당일 소식과 이미지는 기존 아침 브리핑에서 누적하며, 이번 과거 점검을 정기 실행마다 반복하지 않습니다. 요약 이미지가 없어도 텍스트 소식을 게시할 수 있습니다. 조회할 때 이미지를 생성하지 않습니다.

- 스타일 기준: 승인한 신문형 구획과 크림 바탕·브라운 선·주황 강조, 제목과 선에만 가벼운 손글씨 느낌을 적용합니다. 본문 글자는 읽기 쉽게 유지합니다. 날짜·제목·내용은 해당 날짜의 확정 본문에 맞추고, 5칸을 채우려고 소식을 추가하거나 이전 날짜 내용을 가져오지 않습니다. 실제 중요 소식 수에 맞춰 구획을 조정합니다. 본문 사실 검증과 선정을 먼저 마친 뒤 그림을 생성합니다.
- 저장: `assets/daily/YYYY-MM-DD.webp`. `coverImage`에는 `src`, `date`, `alt`, `width`, `height`를 적습니다. `date`는 해당 daily의 날짜와 같아야 하고 너비·높이는 실제 이미지 값이어야 합니다. 생성일이 다른 옛 이미지를 오늘 이미지로 연결하지 않습니다.
- 검증: 이미지 속 날짜·제목·요약·저장소 이름을 해당 날짜 본문과 대조합니다. 본문과 불일치하는 그림은 요약으로 노출하지 않습니다. 일치하는 그림을 검증하기 전에는 불일치하는 `coverImage` 연결을 노출하지 않습니다. 발표 사실, 해석, 미실행 활용 제안을 구분합니다. 이미지의 AI 요약 표기와 본문의 원문 링크를 유지합니다.
- 실패: 생성·내용 검증에 실패하면 그날 `coverImage`를 생략하고 텍스트 데일리를 게시합니다. 이전 날짜 이미지를 대신 붙이지 않습니다. 게시 후 이미지 파일 로딩에 실패하면 이미지 영역만 숨기고 본문은 계속 표시합니다.
- 모바일: 전체 비율로 표시하고 ‘크게 보기’ 링크로 원본 크기를 엽니다. 상세 텍스트·원문·지난 데일리를 유지합니다. 이미지 필드가 없는 과거 기록은 기존대로 읽을 수 있습니다.

기존 기록: 2026-10-29 이미지에는 하단에 ‘디자인 시안’ 표기가 남아 있습니다. 공식 제품 화면이나 실행 결과가 아닌 당시 본문의 요약 삽화입니다. ThinkRail·BAMA는 전날 자료를 완료 기준이라는 관점에서 재소개한 항목이며 신규 출시가 아닙니다. 이 기록은 이후 소식을 같은 주제로 채우거나 해당 그림을 계속 노출하라는 지침이 아닙니다.


## 인사이트 노트 이미지

`#library`는 웹에서 같은 폭의 세 행으로 원자료와 요약을 보여줍니다. 순서는 김덕진 → 치과 AX → 하용호입니다. 각 행의 왼쪽에는 실제 원자료의 대표 표지를 공통 프레임으로 표시합니다. 대표 표지·제목·‘핵심 요약’은 같은 상세 글을 현재 탭에서 엽니다. 별도의 ‘원문 보기’는 공개 원문을 새 탭에서 엽니다. 작은 화면에서는 대표 표지 다음에 소개가 세로로 이어집니다. Monthly는 상단 탭에서 기존 발표와 4편 후속 소개 한 장을 엽니다. Herdr는 기존 Monthly의 다음 소개로만 보관합니다.

- 김덕진 글 ID `ai2027-delegation-2026-10-29`와 하용호 글 ID `ai-development-principles-2026-10-29`를 보존합니다.
- 치과 AX 글 ID `dental-ax-workflow-2026-10-29`는 업무 흐름 연결, AI 초안·추정과 사람 검토, 운영 예외 대응 세 관점을 정리합니다. 1–3편 캡처 쪽수와 4편 부록 근거를 남기고 해석·활용 제안을 구분합니다.
- `sourcePreview`는 원자료의 `title`, `byline`과 선택 이미지 `src`, `alt`, `width`, `height`, `caption`입니다. 김덕진은 사용자가 제공한 강연 자료 첫 장의 축소 표지를 사용하고 상세 글을 연결합니다. 하용호는 공개 PDF의 실제 첫 장 축소본을 사용합니다. 치과는 사용자가 지정한 원문 희망편 포스터를 사용하며, 포스터 속 표현을 실제 성과로 보증하지 않습니다. 원본 이미지의 색·글자·비율을 유지하고 공통 크림색 여백·브라운 테두리·주황 분류 표시로 묶습니다. 이미지가 실패하면 같은 상세 글로 연결하는 제목 안내 표지를 보여줍니다. 상세 글에는 별도의 원문 링크를 유지합니다.
- 요약 노트 이미지는 상세 글에서 전체 비율로 표시합니다. 홈·인사이트 목록의 대표 표지와 구분합니다. `noteImage`는 `src`, `alt`, `width`, `height`, `caption`이며 경로는 `assets/insights/글id.webp`입니다. 전체 비율과 확대 링크를 유지하고, 로딩 실패 시 본문은 계속 읽을 수 있습니다. 그림은 AI 라운지의 요약·활용 해석을 담은 AI 생성 삽화입니다.
- 데일리는 인사이트 목록에 넣지 않습니다. 기존 데일리 8개 날짜(2026-10-21, 23–29)는 날짜별 본문으로 요약 그림을 제공하고, 이후에도 당일 이미지 운영을 이어갑니다. Weekly 종합은 추후 검토하며 이번 변경에 추가하지 않습니다.

인사이트 정렬과 목록 날짜는 선택 필드 `sourceMonth`(원자료의 실제 발표 월, `YYYY-MM`)를 우선합니다. 필드가 없으면 기존 게시 날짜의 월을 사용합니다. 게시 날짜 `date`와 상세 글의 게시일은 바꾸지 않습니다. 같은 원자료 월이면 게시일, 글 ID 순으로 결정합니다. 현재 읽기 순서는 김덕진(2026-10) → 치과 AX(2026-10) → 하용호(2025-07)이며, Monthly는 독립 탭입니다.


## 개인 프로젝트의 편집 방향

홈은 김덕진 AI 2027 공개 강연의 실제 대표 표지와 세 가지 관점을 먼저 소개합니다. 최신 데일리, 다른 인사이트, Monthly 자료를 이어서 읽습니다. 본문은 공개 출처와 개인적인 활용 해석을 구분하며 회사·사내 회의·비공개 업무 자료를 포함하지 않습니다. 치과 Monthly는 원문 작성자가 공개한 경험으로 표시하고, 패러디 포스터는 원문 보조 자료 펼침 영역에 보관합니다.

디자인은 기존 Book Club과 Homewise의 크림 종이·오렌지·짙은 브라운 계열과 명조 제목·나눔 본문을 참고합니다. 브랜드 로고·장식은 사용하지 않습니다. 홈·인사이트의 스크롤 모션은 한 번만 실행하며 기본 내용은 항상 보입니다. 동작 감소 설정이나 API 미지원 환경에서는 모션 없이 읽습니다.

홈 링크의 공유 미리보기는 첫 소개인 김덕진 강연의 실제 표지 축소본과 소개를 사용합니다. 해시 기반 상세 주소도 동일한 정적 메타데이터를 공유하며, 글별 미리보기로 표시하지 않습니다.

## 월별 목록과 메뉴 검증

메뉴 표시 이름은 ‘홈 · AI 소식 · 인사이트 · 함께 보기’로 통일합니다. `assets/app.js`의 `navigationLabels`에서 관리하며, 공유 주소의 `home`, `daily`, `library`, `monthly` ID는 유지합니다. 모바일 메뉴는 같은 높이의 네 열을 사용합니다. 활성 글자의 굵기가 바뀌어도 열 위치는 바뀌지 않습니다. 월별 목록에는 발표 동작을 실행하지 않고, 선택한 월의 상세에서만 키보드 이동·목차·이미지 확대를 시작합니다.

`npm run check`에는 월별 목록, 없는 월, 빈 목록, 같은 월 복수 자료, 기존 공유 주소, 화면 전환 시 발표 상태 정리를 확인하는 라우트 검사가 포함됩니다. 이 검사는 브라우저 실제 화면 검증을 대신하지 않습니다.

### 데스크톱 읽기와 기본 연결

1024px 이상에서 AI 소식의 본문은 18px, 기사 소제목은 26px, 구역 제목은 28px로 표시합니다. GitHub 레이더가 없는 날짜는 빈 보조 열 없이 하나의 읽기 열을 사용합니다. 목차를 누르면 고정 메뉴 아래에서 해당 항목의 제목이 보이도록 이동합니다. 홈과 인사이트의 대표 표지는 상세 글, 월별 표지는 해당 월의 발표 자료를 엽니다. 요약 이미지의 ‘크게 보기’는 원본 이미지를 별도로 엽니다.
