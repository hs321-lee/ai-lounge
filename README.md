# AI 라운지 · AI Lounge

**AI 소식부터, 나는 이렇게 쓴다까지.** 매일 모으고, 매달 고르고, 직접 써본 경험을 나누는 공간입니다.

## 바로가기

Pages 설정을 한 번 완료하면 아래 주소를 계속 사용합니다. 설정·배포 성공 전에는 페이지가 열리지 않을 수 있습니다.

| 데일리 리포트 | https://hs321-lee.github.io/ai-lounge/#daily |

## 자료를 쌓는 방식

기존 아침 브리핑의 AI 관련 내용과 작업공간에서 공유한 자료를 기록으로 정리하고, `data/posts.json`에 추가해 검증한 뒤 바로 저장소에 반영합니다.

- **월간 공유:** 한 달에 한 번 소개할 동향·작은 팁·직접 사용한 사례를 선별합니다.
- **데일리 리포트:** 기존 아침 브리핑에서 AI 관련 내용만 가져와 날짜와 원문 출처를 붙여 누적합니다. 다른 주제는 이 페이지에 옮기지 않습니다.
- `main`에 반영되면 Pages 워크플로가 콘텐츠 검사 후 사이트를 갱신합니다. 배포 완료까지 시간이 걸릴 수 있습니다.

기존 브리핑 작업을 재사용하며, 이 저장소에 별도 AI 수집기나 추가 실행 일정을 만들지 않습니다. 같은 날짜의 데일리 기록은 중복 생성하지 않고 기존 항목을 보완합니다. 발행할 때 원문 링크를 확인하고, 출처를 확보하지 못한 소식은 사실로 옮기지 않습니다.

## 첫 버전

- **대시보드:** 발행 현황과 최근 기록, 공유 방법
- **월간 공유:** 추려서 소개할 AI 동향, 실제 사용 사례, 소소한 팁
- **데일리 리포트:** 출처와 날짜를 갖춘 시스템 보고 기록
- 제목·본문·태그 검색과 주제 필터, 개별 기록 주소, 모바일 화면

현재 월간 공유는 **0건**, 데일리 리포트는 **1건**입니다. 2026-10-21 기존 브리핑에서 AI 소식을 골라 공식 출처로 확인한 첫 기록과 시작 가이드가 들어 있습니다. 기존 브리핑 작업에는 AI 소식의 저장소 반영 지침을 연결했으며, 다음 예약 실행의 자동 반영 결과는 아직 확인 전입니다. 화면의 수치는 실제 콘텐츠에서 계산합니다.

## 실행

빌드나 패키지 설치 없이 실행합니다. JSON을 읽으므로 HTML 파일을 직접 열지 말고 로컬 서버를 사용합니다.

```sh
python -m http.server 8080
```

브라우저에서 `http://localhost:8080`을 엽니다.

```sh
npm run check
```

Node.js 20 이상에서 JavaScript 문법과 콘텐츠 형식·중복 ID·날짜·출처를 검사합니다.

## 콘텐츠 추가

1. `templates/monthly.json` 또는 `templates/daily.json`의 항목을 복사합니다.
2. `data/posts.json`의 `posts` 배열에 넣고 실제 내용으로 채웁니다. 템플릿 파일은 직접 표시되지 않습니다.
3. 날짜는 `YYYY-MM-DD`, `id`는 영문 소문자·숫자·하이픈으로 고유하게 정합니다.
4. 최신 기록부터 날짜 내림차순으로 표시됩니다. 주소는 `#post/고유-id`입니다.
5. `npm run check`를 실행하고 브라우저에서 확인합니다.

### 공통 데이터 계약

| 필드 | 내용 |
| --- | --- |
| `id` | 고유한 영문 ID |
| `type` | `guide`, `monthly`, `daily` |
| `date` | 발행일 `YYYY-MM-DD` |
| `title`, `summary`, `author` | 제목, 짧은 요약, 작성자·시스템명 |
| `tags` | 주제 문자열 배열 |
| `sections` | `{ "heading": "소제목", "body": "본문" }` 배열. 본문은 일반 텍스트이며 줄바꿈 지원 |
| `sources` | `{ "title": "원문 이름", "url": "https://…" }` 배열 |

데일리 리포트에는 최소 하나의 HTTPS 원문 출처가 필요합니다. 월간 공유도 외부 소식을 인용할 때 원문을 붙입니다. 사용하지 않은 도구를 사용 사례로 쓰거나 측정하지 않은 효과를 수치로 제시하지 않습니다. 공개 저장소이므로 회사 내부 코드, 고객 정보, 사내 링크, 비밀키를 올리지 않습니다.

## 사이트 최초 공개 설정

1. [Settings → Pages](https://github.com/hs321-lee/ai-lounge/settings/pages)의 **Build and deployment → Source → GitHub Actions**를 선택합니다.
2. [Publish AI Lounge](https://github.com/hs321-lee/ai-lounge/actions/workflows/pages.yml)에서 **Run workflow**를 실행합니다. 이후에는 `main` 반영 때마다 자동 실행됩니다.
3. 워크플로 성공과 실제 사이트 접근을 확인합니다. 설정 전에는 웹사이트가 배포된 것으로 간주하지 않습니다.

배포에는 기본 `GITHUB_TOKEN`만 사용하며 별도 비밀키는 필요하지 않습니다. 최초 Pages 활성화는 저장소 설정에서 한 번 수행해야 합니다. 공개 파일은 `index.html`, `assets/`, `data/`, `.nojekyll`로 한정합니다. 이전 상태로 되돌리려면 해당 변경을 revert하고 `main`에 반영하면 같은 검사·배포 흐름을 거칩니다.

## 구조

```text
index.html          사이트 진입점
assets/             스타일·브라우저 로직·아이콘
data/posts.json     화면에 표시하는 기록
templates/          발행용 작성 양식
scripts/            콘텐츠 검증
.github/workflows/  자동 형식 검사
```
