# AI 라운지 · AI Lounge

매일 AI 소식을 바로 읽는 개인 대시보드와, 그중 추려 소개하는 별도의 월간 발표 페이지입니다.

## 용도별 화면

| 용도 | 바로가기 | 동작 |
| --- | --- | --- |
| 나의 데일리 읽기 | https://hs321-lee.github.io/ai-lounge/#home | 최신 AI 브리핑 본문과 원문을 바로 표시 |
| 인사이트 모음 | https://hs321-lee.github.io/ai-lounge/#library | 원자료와 핵심 세 가지 요약을 각각 열기 |

| 10월 소개 | https://hs321-lee.github.io/ai-lounge/#post/monthly-2026-10 | 이번 달 소개 초안 |

기본 주소와 `#daily`도 데일리 읽기를 엽니다. 여러 메뉴를 거쳐 들어가는 허브 대신, 각 주소에서 바로 내용을 읽습니다. 발표 화면에는 데일리·대시보드 메뉴를 표시하지 않습니다.

모든 화면과 저장소는 공개 상태입니다. 용도별 화면 분리는 접근 제한이나 비공개 처리가 아니므로 비공개 자료는 저장하지 않습니다.

## 이번 달 구성

데스크톱 발표용 월간 소개입니다. 표지 → 1편 → 2편 → 3편 → 다음 소개(Herdr) 순서로, 한 화면에 한 장면씩 보여 줍니다.

1. 치과 AX 전환기 1–3편: 각 편의 원문 링크와 원문에 실린 캡처를 그대로 사용 (자르거나 새로 가리지 않음, 검은 가림은 원문 작성자가 한 것)
2. 다음 소개 · Herdr: 한 줄 소개, 핵심 기능, 에이전트 스킬 설치 명령. 이미지는 Herdr 공식 저장소(Apache-2.0)의 스크린샷

수치는 작성자 보고이며 독립 검증한 값이 아닙니다. PDF 원본은 올리지 않습니다.

발표 조작:

- `→` / `←`: 다음·이전 장면으로 이동
- 표지 카드의 `바로 가기`: 해당 편으로 이동, `원문 ↗`: 원문 새 창
- 화면 클릭: 원본 해상도로 크게 보기, `Esc` 또는 `닫기`로 나가며 초점이 원래 화면으로 돌아옴

모든 장면은 스크립트 없이도 보입니다. 모션은 장면이 들어올 때 한 번 26px 상승·페이드하고, 모션 감소 설정에서는 꺼집니다. 1100px 이하에서는 한 줄 배치로 바뀝니다.

## 자료를 쌓고 반영하기

작업공간에서 준 자료와 사용 경험을 정리해 월간 소개에 바로 반영합니다. 기존 아침 브리핑의 AI 부분은 준비 자료로 계속 누적하고, 월간 발표에 쓸 내용만 골라 올립니다.

- 원본 데이터: `data/posts.json`
- 데일리 화면: `type: daily` 최신 기록의 날짜·오늘 핵심 → 번호 목차 → AI 인사이트 → GitHub·스킬 발견 → 오늘의 실험을 표시. 모바일은 1열이며 기본 요약은 바로 읽고 상세·설치·주의점·집계 근거는 펼칩니다.
- 월간 발표: `type: monthly` 항목만 별도로 표시
- `type: guide`는 `published: true`인 자료만 인사이트 모음에 표시
- 같은 날짜의 데일리 기록은 중복 생성하지 않고 보완
- 데일리 내부 `monthlyCandidates`에 선별 이유와 출처만 누적하며, 월간 글은 별도 편집 후 발행

기존 브리핑 일정과 데이터 계약을 그대로 쓰며 별도 AI 수집기나 추가 일정을 만들지 않습니다. 외부 소식을 반영할 때 원문과 날짜를 확인하고, 개인 경험과 활용 제안을 구분합니다.

### 데일리 편집 기준

채팅의 관심사 뉴스 5건과 같은 실행에서 공개 AI 데일리를 충분히 채웁니다. AI 뉴스 두 줄을 발췌하는 데서 끝내지 않고, 보통 **AI 인사이트 2–3건 + GitHub·스킬 레이더 2건 + 실행 레시피 1건**을 목표로 합니다. 근거가 부족한 날은 수를 억지로 맞추지 않고 확인 범위를 설명합니다.

- **인사이트:** 공식 발표의 사실, 해석, 오늘 적용할 행동을 분리합니다. 최근 24시간을 먼저 확인하고 부족하면 7일로 넓힙니다.
- **GitHub·스킬:** 실제 README·릴리스·커밋·라이선스를 확인합니다. 용도, 선정 이유, 시작 방법, 제약과 관찰 날짜를 적습니다. GitHub Trending 순위나 기간별 Stars 증가를 직접 확인한 경우에만 '급상승'이라 적고 근거·기간을 붙입니다. 누적 Stars는 날짜가 있는 스냅샷이며 증가량이 아닙니다. 근거가 없으면 '추천 저장소'로 표시합니다.
- **레시피:** 오늘 자료와 연결되는 작은 실험, 단계, 요청 예시와 성공 조건을 적습니다. 실행하지 않았다면 활용 제안이라고 표시합니다.
- **중복:** 같은 저장소를 매일 다시 추천하지 않습니다. 중요한 업데이트·새 활용·후속 검증이 있을 때 변경점을 설명합니다.
- **모바일 편집:** `title`은 오늘의 핵심 한 문장, `sections[].heading`과 `radar[].headline`은 얻을 수 있는 변화·용도가 드러나는 짧은 제목으로 씁니다. 인사이트 `summary`는 사실 1–2문장, `relevance`는 의미·활용 대상 한 문장입니다. 요약은 CSS로 잘라 숨기지 않고 편집으로 짧게 유지합니다. 전체 `body`, 해석 `takeaway`, 실행 `action`은 상세에 보존합니다. 기존 기록에 새 필드가 없으면 본문을 그대로 보여 줍니다. 목차는 실제 항목에서 자동 생성되며, 레시피 프롬프트는 복사 버튼과 수동 선택을 지원합니다.
- **월간 후보:** 데일리 중 소개할 만한 내용만 `monthlyCandidates`에 남깁니다. 후보 추가는 월간 발행이 아니며 월간 화면에 자동 노출하지 않습니다.

## 실행·검사

```sh
python -m http.server 8080
```

`http://localhost:8080`에서 확인합니다. JSON을 읽으므로 HTML을 직접 열지 말고 서버로 실행합니다.

```sh
npm run check
```

Node.js 20 이상에서 JavaScript 문법과 콘텐츠의 필수 필드·중복 ID·날짜·HTTPS 출처를 검사합니다.

## 콘텐츠 계약

`templates/monthly.json` 또는 `templates/daily.json`을 복사해 `data/posts.json`의 `posts` 배열에 추가합니다. 템플릿은 화면에 직접 표시되지 않습니다.

| 필드 | 내용 |
| --- | --- |
| `id` | 영문 소문자·숫자·하이픈으로 만든 고유 ID |
| `type` | `monthly`, `daily`, `guide` |
| `date` | `YYYY-MM-DD` |
| `title`, `summary`, `author` | 제목, 요약, 작성자 |
| `tags` | 주제 문자열 배열 |
| `sections` | `{ "heading": "소제목", "body": "본문" }` 배열. 일반 텍스트·줄바꿈 지원. 월간 기록은 한 항목이 발표 장면 하나 |
| `sections[].kind` | 선택 항목: `"chapter"`이면 편 구분 화면. `part`(예: `1편`), `date`, `url`(원문) 필요 |
| `sections[].media` | 선택 항목: 이미지 배열. 각 항목은 `src`, `width`, `height`, `alt`, `caption`. `assets/dental/`, `assets/herdr/`의 파일만 사용 |
| `sections[].stats` | 선택 항목: `{ "value": "77%", "label": "설명" }` 배열 |
| `sections[].points`, `steps`, `code` | 선택 항목: 문자열 배열. 요점 목록, 단계 흐름, 명령어 블록 |
| `sources` | `{ "title": "원문 이름", "url": "https://…" }` 배열 |
| `highlights` | 선택: 첫 화면 핵심 문자열 최대 3개 |
| 데일리 `sections[].label`, `date`, `takeaway`, `action`, `url` | 선택: 분류·발표 날짜·해석·활용 행동·공식 원문. 기존 `heading`, `body`와 함께 사용 |
| 데일리 `sections[].summary`, `relevance` | 선택: 기본 표시할 짧은 사실 요약·왜 중요한지 한 문장. `summary`가 있으면 전체 `body`·해석·실행은 native details로 펼쳐 읽기 |
| `radar` | 선택: `{label, repo, url, description, signal, checkedAt, sourceUrl, why, try, limitation}` 배열. 검증된 GitHub 저장소, 선정 근거와 관찰 날짜. 선택 `headline`은 용도가 드러나는 짧은 제목 |
| `recipe` | 선택: `{heading, description, steps:[], prompt, limitation}`. 실행해 볼 절차와 요청 예시 |
| `monthlyCandidates` | 선택: `{title, reason, url}` 배열. 준비 데이터만 저장하며 월간 발표 자동 발행 금지 |

월간 기록은 최신 날짜부터 선택되며, 각 `sections` 항목이 발표 장면 한 개입니다. 초안은 제목·요약에 준비 상태를 명확히 적습니다. 데일리 기록은 최소 한 개의 HTTPS 원문이 필요합니다.

## 배포

현재 GitHub Pages는 **main / (root)**를 소스로 사용합니다. `main`에 반영하면 GitHub의 기본 Pages 빌드·배포가 실행됩니다. 별도의 Actions Pages 워크플로로 바꾸지 않습니다. 콘텐츠 검사는 `Validate content`에서 별도로 실행됩니다.

이전 상태로 되돌리려면 변경을 revert해 `main`에 반영합니다. 회사 내부 정보·개인정보·비밀키·비공개 자료는 공개 저장소에 올리지 않습니다.

## 데일리 상단 요약 이미지

기존 오전 8시(KST, 유동 가능) 브리핑 실행에서 그날 공개할 데일리 본문을 확정한 뒤 요약 이미지를 하루 한 번 만듭니다. 별도 예약·수집기를 추가하지 않습니다. 본문·공식 출처와 날짜를 대조한 뒤 이미지와 같은 날짜 daily를 함께 반영합니다. 조회할 때 이미지를 생성하지 않습니다.

- 스타일 기준: `assets/daily/2026-10-29.webp`. 흰 바탕, 굵은 손글씨 한글, 파란 번호와 구획, 손그림 삽화, 상단 큰 항목 2개와 하단 항목 3개, 노란 한 줄 요약을 유지합니다. 다음 생성 때 이 이미지를 스타일 참고로 제공하되, 날짜·제목·본문은 당일 검증된 내용으로 바꿉니다. 텍스트와 삽화를 함께 생성한 방식을 유지하며 실제 폰트 조판으로 대체하지 않습니다.
- 저장: `assets/daily/YYYY-MM-DD.webp`. `coverImage`에는 `src`, `date`, `alt`, `width`, `height`를 적습니다. `date`는 해당 daily의 날짜와 같아야 하고 너비·높이는 실제 이미지 값이어야 합니다. 생성일이 다른 옛 이미지를 오늘 이미지로 연결하지 않습니다.
- 검증: 이미지 속 날짜·제목·요약·저장소 이름을 당일 본문과 대조합니다. 발표 사실, 해석, 미실행 활용 제안을 구분합니다. 이미지의 AI 요약 표기와 본문의 원문 링크를 유지합니다.
- 실패: 생성·내용 검증에 실패하면 그날 `coverImage`를 생략하고 텍스트 데일리를 게시합니다. 이전 날짜 이미지를 대신 붙이지 않습니다. 게시 후 이미지 파일 로딩에 실패하면 이미지 영역만 숨기고 본문은 계속 표시합니다.
- 모바일: 전체 비율로 표시하고 ‘크게 보기’ 링크로 원본 크기를 엽니다. 상세 텍스트·원문·지난 데일리를 유지합니다. 이미지 필드가 없는 과거 기록은 기존대로 읽을 수 있습니다.

2026-10-29 이미지는 당일 채택한 AI 생성 통합 이미지이며, 하단에 ‘디자인 시안’ 표기가 남아 있습니다. 공식 제품 화면이나 실행 결과가 아닌 요약 삽화로 제공합니다. ThinkRail·BAMA는 전날 자료를 완료 기준이라는 관점에서 재소개했으며 신규 출시로 표시하지 않습니다.


## 인사이트 노트 이미지

`#library`는 웹에서 같은 폭의 세 행으로 원자료와 요약을 보여줍니다. 순서는 김덕진 → 치과 AX → 하용호입니다. 각 행의 왼쪽 원자료 안내·대표 사진과 ‘원문 보기’는 공개 원문을 열고, 제목과 ‘핵심 요약’은 독립된 상세 글을 엽니다. 작은 화면에서는 사진 다음에 소개가 세로로 이어집니다. Monthly는 상단 탭에서 기존 35장 발표를 그대로 엽니다. Herdr는 기존 Monthly의 다음 소개로만 보관합니다.

- 김덕진 글 ID `ai2027-delegation-2026-10-29`와 하용호 글 ID `ai-development-principles-2026-10-29`를 보존합니다.
- 치과 AX 글 ID `dental-ax-workflow-2026-10-29`는 업무 흐름 연결, AI 초안·추정과 사람 검토, 운영 예외 대응 세 관점을 정리합니다. 1–3편 원문과 캡처 쪽수를 남기고 해석·활용 제안을 구분합니다.
- `sourcePreview`는 원자료의 `title`, `byline`과 선택 이미지 `src`, `alt`, `width`, `height`, `caption`입니다. 김덕진은 사용자가 제공한 강연 자료 첫 장의 축소 표지를 사용하고 원문을 연결합니다. 하용호는 원문 메타데이터에 썸네일이 없어 제목·저자·발표 시점이 있는 텍스트 안내 표지임을 밝힙니다. 치과 대표 사진은 기존 공개 캡처입니다. 이미지가 실패하면 제목 안내와 원문 링크를 보여줍니다.
- 노트 이미지는 상세 글에서만 표시합니다. `noteImage`는 `src`, `alt`, `width`, `height`, `caption`이며 경로는 `assets/insights/글id.webp`입니다. 전체 비율과 확대 링크를 유지하고, 로딩 실패 시 본문은 계속 읽을 수 있습니다. 그림은 AI 라운지의 요약·활용 해석을 담은 AI 생성 삽화입니다.
- 데일리는 인사이트 목록에 넣지 않습니다. 2026-10-29부터 당일 이미지 운영을 시작하고 과거 데일리는 소급 생성하지 않습니다. Weekly 종합은 추후 검토하며 이번 변경에 추가하지 않습니다.

인사이트 정렬과 목록 날짜는 선택 필드 `sourceMonth`(원자료의 실제 발표 월, `YYYY-MM`)를 우선합니다. 필드가 없으면 기존 게시 날짜의 월을 사용합니다. 게시 날짜 `date`와 상세 글의 게시일은 바꾸지 않습니다. 같은 원자료 월이면 게시일, 글 ID 순으로 결정합니다. 현재 읽기 순서는 김덕진(2026-10) → 치과 AX(2026-10) → 하용호(2025-07)이며, Monthly는 독립 탭입니다.
