# AI 라운지 · AI Lounge

매일 AI 소식을 바로 읽는 개인 대시보드와, 그중 추려 소개하는 별도의 월간 발표 페이지입니다.

## 두 개의 독립 화면

| 용도 | 바로가기 | 동작 |
| --- | --- | --- |
| 나의 데일리 읽기 | https://hs321-lee.github.io/ai-lounge/#home | 최신 AI 브리핑 본문과 원문을 바로 표시 |
| 월간 발표·소개 | https://hs321-lee.github.io/ai-lounge/#monthly | 추린 월간 주제만 보여주는 별도 발표 화면 |
| 10월 소개 | https://hs321-lee.github.io/ai-lounge/#post/monthly-2026-10 | 이번 달 소개 초안 |

기본 주소와 `#daily`도 데일리 읽기를 엽니다. 여러 메뉴를 거쳐 들어가는 허브 대신, 각 주소에서 바로 내용을 읽습니다. 발표 화면에는 데일리·대시보드 메뉴를 표시하지 않습니다.

두 화면과 저장소는 모두 공개 상태입니다. 용도별 화면 분리는 접근 제한이나 비공개 처리가 아니므로 비공개 자료는 저장하지 않습니다.

## 이번 달 구성

데스크톱 발표용 월간 소개입니다. 표지 → 1편 → 2편 → 3편 → 다음 소개(Herdr) 순서로, 한 화면에 한 장면씩 보여 줍니다.

1. 치과 AX 전환기 1–3편: 각 편의 원문 링크와 원문에 실린 캡처를 그대로 사용 (자르거나 새로 가리지 않음, 검은 가림은 원문 작성자가 한 것)
2. 다음 소개 · Herdr: 한 줄 소개, 핵심 기능, 에이전트 스킬 설치 명령. 이미지는 Herdr 공식 저장소(Apache-2.0)의 스크린샷

수치는 작성자 보고이며 독립 검증한 값이 아닙니다. PDF 원본은 올리지 않습니다.

발표 조작:

- `→` / `←`: 다음·이전 장면으로 이동
- 표지 카드의 `바로 가기`: 해당 편으로 이동, `원문 ↗`: 원문 새 창
- 화면 클릭: 원본 해상도로 크게 보기, `Esc` 또는 `닫기`로 나가며 초점이 원래 화면으로 돌아옴

모든 장면은 스크립트 없이도 보입니다. 모션은 장면이 들어올 때 한 번 26px 상승·페이드하고, 모션 감소 설정에서는 꺼집니다. 1100px 이하에서는 한 줄 배치로 바뀝니다.

## 자료를 쌓고 반영하기

작업공간에서 준 자료와 사용 경험을 정리해 월간 소개에 바로 반영합니다. 기존 아침 브리핑의 AI 부분은 준비 자료로 계속 누적하고, 월간 발표에 쓸 내용만 골라 올립니다.

- 원본 데이터: `data/posts.json`
- 데일리 화면: `type: daily` 최신 기록의 핵심 3줄 → AI 인사이트 → GitHub·스킬 레이더 → 실전 레시피·원문을 바로 표시
- 월간 발표: `type: monthly` 항목만 별도로 표시
- `type: guide`는 준비 자료로 보관
- 같은 날짜의 데일리 기록은 중복 생성하지 않고 보완
- 데일리 내부 `monthlyCandidates`에 선별 이유와 출처만 누적하며, 월간 글은 별도 편집 후 발행

기존 브리핑 일정과 데이터 계약을 그대로 쓰며 별도 AI 수집기나 추가 일정을 만들지 않습니다. 외부 소식을 반영할 때 원문과 날짜를 확인하고, 개인 경험과 활용 제안을 구분합니다.

### 데일리 편집 기준

채팅의 관심사 뉴스 5건과 같은 실행에서 공개 AI 데일리를 충분히 채웁니다. AI 뉴스 두 줄을 발췌하는 데서 끝내지 않고, 보통 **AI 인사이트 2–3건 + GitHub·스킬 레이더 2건 + 실행 레시피 1건**을 목표로 합니다. 근거가 부족한 날은 수를 억지로 맞추지 않고 확인 범위를 설명합니다.

- **인사이트:** 공식 발표의 사실, 해석, 오늘 적용할 행동을 분리합니다. 최근 24시간을 먼저 확인하고 부족하면 7일로 넓힙니다.
- **GitHub·스킬:** 실제 README·릴리스·커밋·라이선스를 확인합니다. 용도, 선정 이유, 시작 방법, 제약과 관찰 날짜를 적습니다. GitHub Trending 순위나 기간별 Stars 증가를 직접 확인한 경우에만 '급상승'이라 적고 근거·기간을 붙입니다. 누적 Stars는 날짜가 있는 스냅샷이며 증가량이 아닙니다. 근거가 없으면 '추천 저장소'로 표시합니다.
- **레시피:** 오늘 자료와 연결되는 작은 실험, 단계, 요청 예시와 성공 조건을 적습니다. 실행하지 않았다면 활용 제안이라고 표시합니다.
- **중복:** 같은 저장소를 매일 다시 추천하지 않습니다. 중요한 업데이트·새 활용·후속 검증이 있을 때 변경점을 설명합니다.
- **월간 후보:** 데일리 중 소개할 만한 내용만 `monthlyCandidates`에 남깁니다. 후보 추가는 월간 발행이 아니며 월간 화면에 자동 노출하지 않습니다.

## 실행·검사

```sh
python -m http.server 8080
```

`http://localhost:8080`에서 확인합니다. JSON을 읽으므로 HTML을 직접 열지 말고 서버로 실행합니다.

```sh
npm run check
```

Node.js 20 이상에서 JavaScript 문법과 콘텐츠의 필수 필드·중복 ID·날짜·HTTPS 출처를 검사합니다.

## 콘텐츠 계약

`templates/monthly.json` 또는 `templates/daily.json`을 복사해 `data/posts.json`의 `posts` 배열에 추가합니다. 템플릿은 화면에 직접 표시되지 않습니다.

| 필드 | 내용 |
| --- | --- |
| `id` | 영문 소문자·숫자·하이픈으로 만든 고유 ID |
| `type` | `monthly`, `daily`, `guide` |
| `date` | `YYYY-MM-DD` |
| `title`, `summary`, `author` | 제목, 요약, 작성자 |
| `tags` | 주제 문자열 배열 |
| `sections` | `{ "heading": "소제목", "body": "본문" }` 배열. 일반 텍스트·줄바꿈 지원. 월간 기록은 한 항목이 발표 장면 하나 |
| `sections[].kind` | 선택 항목: `"chapter"`이면 편 구분 화면. `part`(예: `1편`), `date`, `url`(원문) 필요 |
| `sections[].media` | 선택 항목: 이미지 배열. 각 항목은 `src`, `width`, `height`, `alt`, `caption`. `assets/dental/`, `assets/herdr/`의 파일만 사용 |
| `sections[].stats` | 선택 항목: `{ "value": "77%", "label": "설명" }` 배열 |
| `sections[].points`, `steps`, `code` | 선택 항목: 문자열 배열. 요점 목록, 단계 흐름, 명령어 블록 |
| `sources` | `{ "title": "원문 이름", "url": "https://…" }` 배열 |
| `highlights` | 선택: 첫 화면 핵심 문자열 최대 3개 |
| 데일리 `sections[].label`, `date`, `takeaway`, `action`, `url` | 선택: 분류·발표 날짜·해석·활용 행동·공식 원문. 기존 `heading`, `body`와 함께 사용 |
| `radar` | 선택: `{label, repo, url, description, signal, checkedAt, sourceUrl, why, try, limitation}` 배열. 검증된 GitHub 저장소, 선정 근거와 관찰 날짜 |
| `recipe` | 선택: `{heading, description, steps:[], prompt, limitation}`. 실행해 볼 절차와 요청 예시 |
| `monthlyCandidates` | 선택: `{title, reason, url}` 배열. 준비 데이터만 저장하며 월간 발표 자동 발행 금지 |

월간 기록은 최신 날짜부터 선택되며, 각 `sections` 항목이 발표 장면 한 개입니다. 초안은 제목·요약에 준비 상태를 명확히 적습니다. 데일리 기록은 최소 한 개의 HTTPS 원문이 필요합니다.

## 배포

현재 GitHub Pages는 **main / (root)**를 소스로 사용합니다. `main`에 반영하면 GitHub의 기본 Pages 빌드·배포가 실행됩니다. 별도의 Actions Pages 워크플로로 바꾸지 않습니다. 콘텐츠 검사는 `Validate content`에서 별도로 실행됩니다.

이전 상태로 되돌리려면 변경을 revert해 `main`에 반영합니다. 회사 내부 정보·개인정보·비밀키·비공개 자료는 공개 저장소에 올리지 않습니다.
